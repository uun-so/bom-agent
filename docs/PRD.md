# PRD｜BOM‑Agent‑Python v1
文档版本：v1
编写人：陈雪楠
项目类型：个人POC项目
目标用户：制造业BOM工程师、物料工程师

## 一、项目背景 & 产品目标
### 1.1 项目背景
制造业BOM（物料清单）来源多样，包含Excel导出BOM、PDF规格书（datasheet）。物料字段经常出现格式混乱、厂商名称写法不统一、MPN带有各类后缀、字段缺失等问题，人工整理、匹配零件库、校验一致性耗时耗力，容易出错。
本项目利用大模型能力自动完成工程文件信息提取、字段归一、零件库匹配、一致性校验，输出标准化BOM并标记需要人工复核的行，减少工程师重复工作量。

### 1.2 产品目标（v1版本）
搭建一条完整BOM处理流水线：
`工程文件提取 → 字段归一化 → 匹配零件库 → 一致性校验 → 输出标准化BOM（人审高亮）`
> v1为POC原型，优先跑通完整业务链路，CLI命令行交互，暂不提供Web可视化界面。

## 二、用户角色
|角色|描述|
|---|---|
|BOM/物料工程师|上传原始BOM文件、零件库文件，获取清洗、匹配、校验之后的标准化BOM，重点查看系统标记需要人工复核的条目|

## 三、功能需求
### 功能1：文件读取与输入
✅支持输入：
1. Excel格式BOM清单
2. Excel零件库文件
3. PDF datasheet（需要DeepSeek API Key用于信息抽取）

> 约束：纯Excel流程可以脱离大模型API运行；PDF信息提取依赖DeepSeek大模型。

### 功能2：工程文件信息提取
1. 读取Excel原始BOM各个字段
2. 解析PDF datasheet，从中抽取物料相关信息
> 痛点：PDF排版不规范，文本容易乱码、字段错位，需要增加文本预处理清洗逻辑

### 功能3：字段归一化
对原始杂乱物料字段做标准化处理，统一字段表达，为后续零件匹配做准备。

### 功能4：零件库匹配
- 精确匹配
- 模糊匹配
将BOM物料和零件库里面料号、厂商、MPN、描述、封装、分类进行匹配，回填对应字段。

> 痛点：MPN经常带有各类后缀（如 /NOPB），直接精确匹配失败；厂商名称有全称、简写、中英文多种写法，v1暂不做完整别名映射，作为v2迭代项。

### 功能5：一致性校验（validate）
校验物料数据存在的各类问题，识别：
- 缺失料号
- 缺失厂商
- 缺失MPN
- 缺失参考位号
- 参考位号重复
- 重复行
- 未匹配零件库物料

### 功能6：结果输出（output）
输出 `.xlsx` 文件，在原始字段基础上追加新字段：
|输出字段|说明|
|匹配状态|精确匹配 / 模糊匹配 / 未匹配|
|匹配料号/厂商/MPN/描述/封装/分类|命中零件库后回填字段|
|校验问题|列出当前行识别到的数据缺陷|
|是否需人工复核|有校验问题 / 匹配不确定 = 是，该行黄色高亮（人审高亮）|

### 功能7：CLI交互运行
通过命令行传入参数执行整条流水线，无需图形界面。
配套脚本可以生成mock测试样例用于调试。

## 四、非功能需求（v1）
1. 运行方式：CLI命令行程序
2. 性能：POC原型，不面向高并发场景
3. AI稳定性：大模型输出存在不确定性，需要反复调试Prompt + 增加校验逻辑，降低AI不稳定带来的错误
4. 依赖管理：通过requirements.txt统一管理Python依赖包
5. 可测试：支持生成mock模拟数据，方便开发自测

## 六、v1 不做
1. Web / 可视化界面
2. 完整厂商别名映射库
3. MPN后缀自动剥离完整逻辑（规划放到v2）
4. 用户账号、权限系统
5. 对接企业ERP/PLM系统

## 七、迭代计划（v2）
- 厂商别名映射（manufacturer alias mapping）
- MPN后缀归一化/剥离，提升匹配成功率
- 优化大模型Prompt，进一步提升信息提取准确率
- 增加Web/可视化界面

## 八、项目难点（风险点）
1. PDF datasheet排版不规范，文本提取容易乱码、字段错位，需要预处理清洗文本
2. MPN带有各类后缀，直接精确匹配失败，后续迭代增加后缀剥离模块
3. 厂商名称写法不统一（全称 / 简写 / 中英文），维护别名映射表解决
4. AI输出结果不稳定，反复调试Prompt，叠加校验逻辑对输出做验证
